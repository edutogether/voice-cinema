# 부트 스플래시 표준 명세

2026-09-09, 대표 지시("구글러 스플래시 보이스 시네마랑 맞추고, 다른 모든 앱도 싹다 거기에 맞춰")로
이 저장소의 스플래시가 전 앱 표준이 됐다. **이 문서는 다른 앱이 그대로 따라 할 수 있게 쓴 명세이고,
참조 구현은 이 저장소의 `index.html` / `src/styles/splash.css` / `src/lib/splash.ts`다.**

---

## 0. 이 명세의 핵심 한 줄

**마크업은 HTML에 정적으로 두고, 사라지는 타이밍은 CSS 애니메이션이 잡고, JS는 다 끝난 노드를
치우는 일만 한다.** 리액트로 그리거나 JS 타이머로 재면 **번들이 로드된 다음부터 시간이 흐르기
시작해** 그만큼 첫 화면이 비고 스플래시가 늦게 사라진다. 이건 취향이 아니라 실측으로 확인한 차이다.

---

## 1. 구조 — `index.html`에 정적으로

`<body>` 맨 앞, 리액트 마운트 지점(`#root`)보다 **위에** 둔다.

```html
<body>
<!-- 스플래시는 정적 마크업으로 둔다 — 리액트가 그리면 번들 로드 전까지 빈 화면이
     잠깐 보인다. 사라지는 시점만 src/lib/splash.ts가 맡는다. -->
<div id="splash">
  <div class="logo">🎬</div>
  <div class="name">InKY <span class="gold">Voice Cinema</span></div>
  <div class="stagline">무성영화에 내 목소리를 더빙해 완성하는 나만의 영화</div>
  <span class="sbar"><i></i></span>
</div>
<div id="root"></div>
<script type="module" src="/src/main.tsx"></script>
</body>
```

**왜 정적이어야 하는가**: 리액트 컴포넌트로 그리면 브라우저가 HTML을 받은 시점엔 `#root`가 비어 있고,
번들을 내려받아 실행하고 마운트할 때까지 **아무것도 없는 화면**이 보인다. 정적 마크업은 첫 페인트부터
보인다(실측: 표시 49~76ms). 이 앱은 리액트 전환 때 컴포넌트로 옮겼다가 이 문제를 발견해 되돌렸다.

**주의 — 인라인 `<script>`는 쓰지 않는다.** 예전에는 여기서 `setTimeout`으로 스플래시를 지웠는데,
CSP가 인라인 스크립트를 해시로만 허용해서 문구를 고칠 때마다 CSP 해시를 같이 고쳐야 했고,
잊으면 배포된 사이트에서만 화면이 죽었다. 타이밍을 CSS로 옮기면 이 문제 자체가 사라진다.

## 2. CSS 전문 — 복사해서 색과 문구만 바꾸면 된다

색은 CSS 변수를 쓴다(`--bg`, `--bg2`, `--cream`, `--muted`, `--gold`, `--gold-soft`).
변수 이름이 다른 앱은 자기 토큰으로 바꾸면 된다.

```css
/* 첫 진입 스플래시.
   #splash가 화면을 완전히 덮는 동안에도 그 아래 body의 무거운 배경(라디얼
   그라디언트 3장)이 같이 그려지고 있어 저사양 기기에서 버벅였다 —
   splash가 떠 있는 동안만 단색으로 바꾼다(사라지면 :has()가 풀려 자동 복귀). */
body:has(#splash) {
  background: var(--bg);
}

/* 사라지는 타이밍을 CSS로 잡는다 — JS 타이머로 시작하면 번들이 로드된 뒤부터
   재는 셈이라 그만큼 늦게 사라진다. CSS 애니메이션은 문서가 그려지는 순간부터
   흐르므로 첫 페인트 기준에 맞는다.
   1800ms 유지 → 500ms 페이드 → 2400ms에 제거. */
#splash {
  animation: splashOut 2400ms ease forwards;
  position: fixed;
  inset: 0;
  z-index: 999;
  display: flex;
  flex-direction: column;
  align-items: center;
  justify-content: center;
  gap: 14px;
  background: linear-gradient(180deg, var(--bg), var(--bg2));
}
@keyframes splashOut {
  0%,
  74.99% {
    opacity: 1;
    pointer-events: auto;
  }
  75% {
    opacity: 1;
    pointer-events: none;
  }
  95.83%,
  100% {
    opacity: 0;
    pointer-events: none;
  }
}

#splash .logo {
  font-size: clamp(48px, 10vw, 72px);
  filter: drop-shadow(0 10px 24px rgba(233, 196, 106, 0.35));
  animation: splashPop 0.6s ease;
}
#splash .name {
  font-size: clamp(26px, 5vw, 38px);
  font-weight: 800;
  letter-spacing: -0.01em;
  color: var(--cream);
}
#splash .stagline {
  font-size: clamp(13px, 2vw, 16px);
  color: var(--muted);
}
#splash .sbar {
  display: block;
  width: 190px;
  height: 3px;
  border-radius: 99px;
  background: rgba(233, 196, 106, 0.2);
  overflow: hidden;
  margin-top: 4px;
}
/* margin이 아니라 transform으로 움직인다 — margin은 매 프레임 레이아웃을
   다시 계산시켜(리플로우) 저사양 기기에서 버벅임의 원인이 된다. */
#splash .sbar i {
  display: block;
  width: 40%;
  height: 100%;
  border-radius: 99px;
  background: linear-gradient(90deg, var(--gold), var(--gold-soft));
  animation: splashBar 1.15s ease-in-out infinite;
  will-change: transform;
}
@keyframes splashPop {
  0% {
    transform: scale(0.6);
    opacity: 0;
  }
  60% {
    transform: scale(1.08);
    opacity: 1;
  }
  100% {
    transform: scale(1);
  }
}
@keyframes splashBar {
  0% {
    transform: translateX(-76px);
  }
  100% {
    transform: translateX(190px);
  }
}
```

앱의 다른 스타일보다 **먼저** 로드되게 한다(이 앱은 `main.tsx`에서 `base.css` 다음, 화면별 CSS보다 앞).

## 3. 타이밍 — 숫자와 그 숫자가 나오는 자리

| 시점 | 값 | 어디서 나오는가 |
|---|---|---|
| 화면에 나타남 | **첫 페인트**(실측 49~76ms) | 정적 마크업이라 HTML 파싱 즉시. JS와 무관 |
| 그대로 유지 | **1800ms** | `splashOut`의 `0%~74.99%` 구간 = 2400ms × 0.75 |
| 페이드 시작 | **1800ms**(실측 1870~1899ms) | `75%` 키프레임에서 opacity가 내려가기 시작 |
| 페이드 길이 | **500ms** | `75% → 95.83%` = 2400ms × 0.2083 |
| 완전 소멸 | **2400ms**(실측 2470~2498ms) | `animationend` → `splash.remove()` |

**실측(같은 조건 3회, 1440×900, 로컬 서빙)**

| 회차 | 표시 | 페이드 시작 | 소멸 |
|---|---|---|---|
| 1 | 76ms | 1870ms | 2470ms |
| 2 | 50ms | 1899ms | 2498ms |
| 3 | 49ms | 1897ms | 2497ms |
| **실행 간 편차** | **27ms** | **29ms** | **28ms** |

**편차를 함께 재는 이유**: 다른 앱이 이 값을 맞췄는지 판단하려면 "몇 ms 차이면 다른 것인가"를
알아야 한다. 같은 코드도 실행마다 27~29ms는 흔들리므로, **그 범위 안의 차이는 구분되지 않는다**.
표시 시각이 실측값보다 큰 폭(수백 ms)으로 늦다면 그건 편차가 아니라 **마크업을 JS로 그리고 있다는
신호**다.

시간을 바꾸고 싶으면 `animation` 길이(2400ms)와 키프레임 퍼센트를 함께 고친다:
`유지시간 ÷ 전체`가 페이드 시작 퍼센트, `(유지시간+페이드) ÷ 전체`가 완전 투명 퍼센트다.

## 4. 사라지는 방식 — `src/lib/splash.ts`

```ts
/**
 * 첫 진입 스플래시를 화면에서 걷어낸다.
 *
 * 마크업은 index.html에 정적으로 두고(리액트가 그리면 번들 로드 전까지 빈 화면이
 * 잠깐 보인다), 사라지는 타이밍은 CSS 애니메이션이 잡는다(문서가 그려지는 순간부터
 * 흐르므로 번들 로드 시간에 밀리지 않는다).
 * 여기서는 그 애니메이션이 끝나면 노드를 실제로 지우는 일만 한다 —
 * 노드가 남아 있으면 `body:has(#splash)`가 계속 매치돼 배경이 안 돌아온다.
 */
export function installSplash(): void {
  const splash = document.getElementById('splash');
  if (!splash) return;

  const remove = () => splash.remove();
  splash.addEventListener('animationend', (e) => {
    if (e.animationName === 'splashOut') remove();
  });

  // 번들이 늦게 실행돼 애니메이션이 이미 끝났을 수도 있다 — 그 경우 바로 지운다.
  if (splash.getAnimations().every((a) => a.playState === 'finished')) remove();
}
```

엔트리에서 **리액트 렌더보다 먼저** 부른다:

```ts
installSplash();
createRoot(document.getElementById('root')!).render(<App />);
```

**JS 타이머를 쓰지 않는 이유(이 명세의 핵심)**: `setTimeout(…, 1800)`은 **그 타이머를 건 시점부터**
1800ms를 잰다. 그 시점은 번들을 내려받아 실행한 뒤이므로, 번들이 무거울수록·회선이 느릴수록
스플래시가 그만큼 더 오래 떠 있는다. 같은 코드가 기기마다 다른 시간 동안 보이는 셈이다.
CSS 애니메이션은 **요소가 그려지는 순간부터** 흐르므로 회선·번들 크기와 무관하게 일정하다.

**JS가 노드를 지워야 하는 이유**: 애니메이션이 끝나도 요소는 `opacity: 0`으로 남아 있어
`body:has(#splash)`가 계속 매치되고, 그러면 스플래시 동안만 쓰던 단색 배경이 원래 배경으로
돌아오지 않는다. `pointer-events: none`이라 클릭을 막지는 않지만 노드는 반드시 치운다.

**늦게 실행됐을 때의 보정**: 번들이 2.4초보다 늦게 실행되면 `animationend`는 이미 지나가 버려
영영 안 지워진다. 그래서 설치 시점에 애니메이션이 이미 끝났는지 확인해 바로 지운다.

## 5. 앱마다 바꾸는 것 / 절대 바꾸지 않는 것

### 바꾼다 (앱 정체성)
| 대상 | 이 앱의 값 |
|---|---|
| 로고 이모지 | `🎬` |
| 앱 이름 | `InKY <span class="gold">Voice Cinema</span>` — 강조할 부분만 `.gold` |
| 한 줄 설명 | `무성영화에 내 목소리를 더빙해 완성하는 나만의 영화` |
| 색 토큰 | `--bg`/`--bg2`/`--cream`/`--muted`/`--gold`/`--gold-soft` |
| 로고 그림자·바 색 | 앱 강조색에 맞춰 |

### 바꾸지 않는다 (표준)
- **구조**: `#splash > .logo / .name / .stagline / .sbar > i`, `#root`보다 위, 정적 마크업
- **타이밍**: 유지 1800ms / 페이드 500ms / 소멸 2400ms, 그리고 그 값이 **CSS 애니메이션에서 나온다는 것**
- **사라지는 방식**: CSS가 타이밍을 잡고 JS는 `animationend`에 노드만 제거 + 늦은 실행 보정
- **레이아웃**: `position: fixed; inset: 0`, 세로 중앙 정렬, `gap: 14px`, `z-index: 999`
- **성능 규칙 2가지**: ①`body:has(#splash)`로 스플래시 동안 무거운 배경을 단색으로 대체
  ②바 애니메이션은 `margin`이 아니라 `transform`(margin은 매 프레임 리플로우를 강제한다)
- **인라인 `<script>` 금지**

## 6. 검증 방법 — "제대로 맞췄는지" 확인하는 법

### ① 첫 페인트에 실제로 보이는가 (가장 중요)
JS 없이도 보여야 한다. 가장 확실한 확인은 **자바스크립트를 끄고 여는 것**이다 — 스플래시가 그대로
보이면 정적 마크업이고, 빈 화면이면 JS가 그리고 있다는 뜻이다.

```js
// Playwright: JS를 끈 컨텍스트에서 스플래시가 보이는지
const ctx = await browser.newContext({ javaScriptEnabled: false });
const page = await ctx.newPage();
await page.goto(URL);
console.log(await page.locator('#splash').isVisible()); // true여야 한다
```

빌드 산출물의 HTML을 직접 봐도 된다 — `dist/index.html`에 `<div id="splash">`가 들어 있어야 한다.

```bash
curl -s https://<라이브주소>/ | grep -c 'id="splash"'   # 1이어야 한다
```

### ② 타이밍 실측 (3회 이상, 편차와 함께)
`performance.now()` 기준으로 표시·페이드 시작·소멸 시각을 잰다. **반드시 3회 이상 재고 실행 간
편차도 같이 본다** — 편차를 모르면 차이가 유의미한지 판단할 수 없다.

```js
await page.addInitScript(() => {
  window.__m = {};
  const t = () => Math.round(performance.now());
  const start = () => {
    const el = document.getElementById('splash');
    if (!el) return;
    window.__m.seen = t();
    new MutationObserver((_, o) => {
      if (!document.getElementById('splash')) { window.__m.gone = t(); o.disconnect(); }
    }).observe(document.body, { childList: true, subtree: true });
    const tick = setInterval(() => {
      const cur = document.getElementById('splash');
      if (!cur) { clearInterval(tick); return; }
      if (parseFloat(getComputedStyle(cur).opacity) < 0.99 && window.__m.fade === undefined) {
        window.__m.fade = t();
      }
    }, 8);
  };
  document.addEventListener('DOMContentLoaded', start);
  if (document.readyState !== 'loading') start();
});
await page.goto(URL);
await page.waitForTimeout(6000);
console.log(await page.evaluate(() => window.__m));
```

**합격 기준**: 표시 100ms 이내, 페이드 시작 1800ms 부근, 소멸 2400ms 부근. 이 앱의 실측값은
49~76 / 1870~1899 / 2470~2498ms이고 실행 간 편차는 27~29ms다.

### ③ 사라진 뒤 배경이 돌아오는가
소멸 후 `#splash` 노드가 DOM에 없어야 하고, `body`의 배경이 원래(그라디언트 등)로 복귀해야 한다.

```js
await page.waitForTimeout(3000);
await page.evaluate(() => ({
  남아있나: !!document.getElementById('splash'),          // false여야 한다
  배경: getComputedStyle(document.body).backgroundImage,  // none이 아니어야 한다
}));
```

### ④ 눈으로 한 번
표시 중(약 900ms 시점)에 스크린샷을 찍어 로고·이름·설명·로딩바가 세로 중앙에 모여 있는지 본다.

## 7. 이 표준이 나온 경위

리액트 전환 때 스플래시를 컴포넌트로 옮겼더니 **번들 로드 전까지 빈 화면이 잠깐 보이는** 회귀가
생겼고, 전환 전과 동시 실행 대조에서 잡혔다. 마크업을 정적으로 되돌린 뒤에도 **JS 타이머로 시간을
재면 번들 로드 시간만큼 늦게 사라지는** 두 번째 문제가 남아, 타이밍을 CSS 애니메이션으로 옮겨
전환 전과 같은 기준(첫 페인트)으로 맞췄다. 그 결과가 위 실측값이다.

즉 이 명세의 두 규칙(**정적 마크업**, **CSS가 타이밍을 잡는다**)은 설계 취향이 아니라 각각
실제 회귀를 하나씩 막은 결과다.
