## 1. 인계 절차 — 양방향 공통

Bumm님이 **"Codex로 인계"** 또는 **"Claude로 인계"**라고 하면 넘기는 쪽이 아래를 그대로 한다.

1. 새 작업 착수를 멈추고, 진행 중인 변경을 안전한 상태로 정리한다.
2. 미커밋 변경을 확인한다. **다른 작업자의 변경은 보존한다**(지우거나 되돌리지 않는다).
3. 이 문서를 갱신하고, **자기 변경만** 작업 가지에 커밋·푸시한다. 미완료 작업은 미완료로 적는다.
4. 원격 반영을 확인하고, 저장소·가지·최종 커밋 전체 SHA·이 문서 경로·다음 작업을 채운 **인수 프롬프트**를 낸다.
5. 넘긴 쪽은 이 앱의 수정을 멈춘다. 다시 인수할 때는 **최신 코드와 이 문서의 변경분부터** 확인하고 이어간다.

- 인계 자체를 위해 전체 검사·전체 감사를 다시 돌리지 않는다.
- 인계 과정에서 **병합·배포·삭제·강제 푸시를 하지 않는다.**
- 인수하는 쪽은 `git fetch` 후 인계 가지와 `master`의 차이, 그리고 아래 §6의 "다른 작업자 가지"부터 본다.

### Apple 모션 원칙을 참고한 전환·왼쪽 소개 정리 (2026-09-30 후속)

Bumm님이 이전 전환에도 끊김과 과한 움직임을 지적했다. Apple iPhone 페이지의 실제 큰 미디어 전환과
[Apple 모션 지침](https://developer.apple.com/design/human-interface-guidelines/motion),
[WWDC 스프링 설명](https://developer.apple.com/videos/play/wwdc2023/10158/)을 참고했다.
반복 입력에도 속도가 이어지고 과한 반동이 없는 원칙을 적용했으며, 수치는 이 화면에 맞춰 조정했다.

이전 프레임별 자바스크립트 갱신을 Web Animations의 transform·opacity 보간으로 교체했다.
현재 진행 시각에서 위치·속도를 이어받고, 키프레임 경계의 속도도 맞췄다. 중앙 확대·주변 축소의
차이를 줄이고 크기 변화의 중앙 꺾임을 없앴다. 순환 경계 이동은 투명한 구간에서 처리한다.
겹침 순서 변경은 필요한 시점에 여섯 장을 함께 갱신한다. 상단 양옆 호버는 이웃 장면으로 한 칸,
하단 썸네일은 원하는 장면으로 바로 이동한다. 고정 포인터의 연쇄 선택·중앙 재진입 역전은 방지한다.

이전 영상은 즉시 정지하되 마지막 프레임을 140ms 페이드 동안 유지하고 160ms 뒤 소스를 해제한다.
그 사이 같은 장면으로 돌아오면 이어 재생한다. 빠른 왕복에서 첫 이미지로 튀는 현상을 줄이기 위한
제한된 보존이며 동시에 소리를 재생하지 않는다. 홈 이탈·움직임 줄이기·탭 숨김의 정리도 유지한다.

왼쪽 소개 폭을 늘려 “10초의 영화.”를 한 줄로 표시했다. 마이크는 72px(낮은 PC 화면 56px)로 줄여
“나만의 더빙 극장” 바로 위에 왼쪽 정렬했다. 타입·빌드·린트와 관련 E2E 37개 통과,
마지막 순환 경계 보정 후 핵심 4개 재실행 통과. 42개 클릭 조합, 모바일 재생, PC 세 크기의
제목 한 줄·마이크 위치를 확인했다.

최종 헤드리스 Chromium 1440×900·CPU 6배 감속·12회 연속 호버: 프레임 간격 p95 16.8ms,
최대 33.3ms, 50ms 초과 0회. 배치 계산 53회·54.2ms, 스타일 계산 265.5ms.
이전 측정도 p95 16.7ms였으므로 FPS 향상을 주장하지 않는다. 동작 연결과 시각적 완급을 조정한
로컬 시안이며 Bumm님의 실제 체감 확인이 남아 있다. 로컬 4322 반영, 미배포·초안 PR #4 유지.

### 연속 호버에서 움직임이 끊기는 문제 수정 (2026-09-30 후속)

Bumm님이 전환이 끊겨 보인다고 지적했다. 기존 정수 위치 + CSS 전환은 순환 경계에서
뒤쪽 카드가 중앙을 횡단하고, 재선택마다 감속 곡선을 다시 시작했다. 현재 위치·속도를
이어받는 임계 감쇠 이동으로 교체했다. 여섯 DOM의 transform·opacity만 프레임마다 갱신하며
React 재렌더나 배치 읽기를 애니메이션 루프 안에서 하지 않는다. 경계 카드는 뒤편에서
완전히 숨긴 상태로 반대편에 배치한다. 선택 즉시 영상 재생 요청은 유지한다.

움직이는 카드의 경계가 마우스 아래로 지나가며 선택을 바꾸지 않도록 고정된 좌·중·우
구역으로 호버 의도를 구분한다. 중앙으로 마우스를 옮길 때는 현재 선택을 유지한다.
설명·영상은 짧게 페이드하며 큰 그림자의 순간 교체도 제거했다. 움직임 줄이기 설정·
홈 이탈·탭 숨김 시에는 목표 위치에 바로 정착시키고 애니메이션 루프를 해제한다.

타입·빌드·린트 통과. 관련 E2E 25개 및 중앙 재진입 보정 후 관련 4개 추가 실행 통과
(고유 시나리오 26개). 순환 경계에서 숨김, 연속 호버 후 정착, 움직임 줄이기,
중앙 진입 시 선택 보존, 42개 클릭 조합과 6개 화면 크기를 확인했다.

동일한 헤드리스 Chromium 1440×900·CPU 6배 감속·12회 연속 호버 비교:
프레임 간격 p95 16.8→16.7ms, 50ms 초과는 전후 0회. 스타일 계산은 171.5→249.6ms로
증가했다. 기존 측정에도 긴 프레임 지연은 없어 FPS 개선을 주장하지 않는다. 이번 수정은
이동 경로·속도·선택의 불연속을 해결한 것이다. 현장 PC의 체감을 보장하는 측정은 아니다.
로컬 4322 반영, 미배포. 공식 원장과 초안 PR #4에 누적한다.
