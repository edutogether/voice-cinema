# 첫 화면 «의견 보내기» — Poster Studio와 똑같이, 11/14 00:00(KST)에 저절로 빠진다

## 문제

11/10 현장 시험과 그 뒤 며칠 동안 선생님들이 쓰다가 불편한 점 · 오류를 바로 알릴 길이 없다.
Poster Studio에는 11/5부터 첫 화면 «의견 보내기»가 있다(Firestore 저장 + Bumm님 카카오톡 알림).
Bumm님이 Voice Cinema에도 같은 것을 넣고, 행사 날(11/14) 0시에 배포 없이 저절로 빠지게 하라고 하셨다.

## 지시가 바뀐 경위(11/8)

1. 첫 지시: 이름 · 연락처 없이 의견 글만, 웹과 설치판 모두. 저장 · 알림 길은 세션이 ⭐ 안(Storage `feedback/` + Resend 메일)으로 만들고 팀장께 결정을 올렸다.
2. Bumm님: «설치판에서는 뺀다»(설치판은 인터넷이 안 되는 것이 기준).
3. Bumm님: «Poster Studio와 똑같이» — Firestore(승인, 무료 범위) · 카카오 «나에게 보내기» · 같은 여섯 칸(이름 포함) · 같은 창 문구 · 90일 자동 삭제와 내보내기 도구 · 이름 수집은 Voice Cinema 방침에 추가.
   Storage · Resend 쪽 코드는 지웠다.

## 원하는 결과

- 웹 첫 화면 오른쪽 위 줄(개인정보처리방침과 같은 줄 · 같은 글자) 맨 왼쪽에 «의견 보내기». 설치판에는 없다.
- 창: 이름(40자, «피드백을 살펴보고 추가로 문의드릴 것이 있을 때를 위해») · 의견(500자). 단추 «취소» · «보내기».
  «함께 보내는 것: 판 번호 · 화면 크기 · 기기 · 단계 / 보내지 않는 것: 녹음한 목소리 · 영화». 휴대폰은 설명글 없이 칸만 작게.
- 서버가 Firestore에 저장하고 Bumm님 카카오톡(나와의 채팅)으로 `[Voice Cinema 의견] 이름 / 의견 / — 판 · 화면 · 기기 · 단계`를 보낸다.
- 받은 지 90일 지난 의견은 매일 지운다. 운영자는 내보내기 도구로 CSV를 받고 지울 수 있다.
- **2026-11-14 00:00(KST)** 부터 화면의 링크와 열린 창이 새로 고치지 않아도 사라지고, 서버는 410으로 거절한다.

## 영향받는 사용자 · 시스템

- 웹 첫 화면. 녹음 · 저장 화면 · 설치판은 바뀌지 않는다.
- Functions: `POST /feedback` · `GET /kakao/start` · `GET /kakao/callback`, 예약 함수 `feedbackMaintenance`(매일 04:00 KST).
- Firestore `(default)`(asia-northeast3, 무료 범위 — 11/8 만듦): `feedback`(의견) · `kakaoAuth`(`owner` 토큰 · `pending` 연결 대기). 규칙은 모두 막음.
- Secret Manager: `KAKAO_REST_API_KEY` · `KAKAO_CLIENT_SECRET`(Poster Studio와 같은 카카오 앱의 값을 옮겨 만듦 — 값은 어디에도 출력하지 않았다).
  배포 계정 `secretmanager.viewer`, 실행 계정 `secretAccessor`(Poster Studio 11/5 결정과 같다).
- 배포: `deploy.yml`이 `firestore:rules`도 함께 낸다.
- 개인정보처리방침: 이름 · 의견 수집, 목적, Firestore 보관 · 90일, 카카오 알림, 11/14 닫힘.

## 제약

- 키 · 토큰을 코드 · 문서 · 로그 · 출력에 남기지 않는다. 새 카카오 앱을 만들지 않는다(Poster Studio 앱에 주소만 더한다 — Bumm님이 직접).
- 로그에 이름 · 의견을 남기지 않는다(문서 번호 · 결과만).
- 동결 기간이다 — 시험 → «배포 직전 한 줄» → 팀장 OK → master push → CI로만 낸다. 11/10 현장 시험 전에 끝낸다.
- Poster Studio 저장소는 읽기만 한다.

## 설계

- 닫힘 시각: `src/config.ts`와 `functions/feedback.js`의 `FEEDBACK_CLOSE_AT`. 계약 검사가 둘과 방침 문구를 대조한다.
- 화면 `src/components/FeedbackLink.tsx` · `src/lib/feedback.ts` · `src/styles/feedback.css` — 값은 Poster Studio(11/5 · 11/7 고친 값) 그대로.
  보내기는 업로드와 같은 머리(`boothHeaders` — 부스 토큰 · App Check). 기다림 15초.
- 서버 `functions/feedback.js`(순수 — 검사 · 닫힘 · 알림 글 · 90일 정리 · 예약 묶음) · `functions/kakao.js`(카카오 연결 · 갱신 · 보내기).
  - 핸들러 순서: 닫힘(410) → `boothGuard`(인증 전 상한 → 부스 토큰 → App Check → 의견 한도 분당 10) → JSON만 · 8kb · 여섯 칸 검사 → 저장(실패 503) → 알림(실패해도 200).
  - 서버가 답하는 시간 10초 + 여유 5초 ≤ 화면 기다림 15초(Poster Studio 11/8 종합감사에서 찾은 «두 번 저장»을 처음부터 막는다).
  - 카카오: 만료 60초 전이면 먼저 갱신, 401이면 한 번만 갱신 뒤 다시. 200자를 넘으면 줄여 보낸다(저장은 원문 그대로).
  - 연결: `state`는 한 번만(해시로 저장 · 거래로 읽고 지움 · 10분). 다른 카카오 계정으로 다시 연결하면 403(덮어쓰지 않는다).
- Poster Studio와 다른 점(일부러): Firestore 한도 계수(IP 10분 10건 · 하루 300건)는 옮기지 않았다 — Voice Cinema는 App Check와 문 검사의 메모리 한도(분당 10)로 막는다.
- 내보내기 `tools/feedback-export.mjs`(Poster Studio `scripts/ops/feedback-export.mjs`와 같은 모양, 프로젝트만 다르다).

   상자는 방침 링크와 같은 24px로 두고, 손가락 기기에서만 투명한 덧칸(`::after`)으로 화면 44px 이상. 위로 7px · 옆으로 4px, 낮은 휴대폰(375×553)을 위해 `z-index:1`.
