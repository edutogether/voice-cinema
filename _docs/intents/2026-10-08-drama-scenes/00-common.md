> «모든 이미지는 ChatGPT에서 그린다. 영상 망치지 않게 최대한 많이 그린다. 그림들은 통일성을 완벽하게 가진다.
> 나한테 검사 맡고 Higgsfield에서 실행한다.»
> + 10/10 밤: «장면들마다 시나리오·스토리보드·대본, 문서로서 필요한 것 싹 다 완성하고, 그림 뭐가 필요한지까지 프롬프트까지
> 세팅해 놔. 그림까지는 다 뽑으려면 다 뽑아 놔도 상관없어. 다만 영상별로 만들기 전에 철저히 검토해야 한다.»

> 3. **그림 결 통일** — 장르 안에서도, 장르와 장르 사이에서도 같은 결(이 문서의 공통부)
> + 10/10 밤 보충: «영상 만들기 전에 그림과 글을 세팅해서 보여 줘서, "이제 이렇게 만들려고 한다"고 허락 맡고 만들어라.»

> 5. **영상은 컷마다 «영상 만들기 전 확인»을 거친다** — 넣을 그림 전부와 넣을 글 전부를 검토 페이지에 세팅해 팀장에게 보내고,

## 2. 공통 시간표 — 여섯 장르가 같은 박자

| 컷 | 문서 id | 다운로드 영상 구간 | 쓰는 길이 | 만드는 길이(Kling 최소) | 그리는 그림 |
|---|---|---|---|---|---|
| ① 미리보기 | `c1` | 0.0–2.5초 | 2.5초 | 3초 | 시작·사이·끝 |
| ③-1 시점 전환 | `c3a` | 2.5–3.5초 | 1초 | 3초 | 시작·끝 |
| ③-2 상대 대사 | `c3b` | 3.5–6.0초 | 2.5초 | 3초 | 시작·사이·끝 |
| ③-3 상대 행동 | `c3c` | 6.0–8.0초 | 2초 | 3초 | 시작·사이·끝 |
| ⑥-1 반격(아이 목소리 자리) | `c6a` | 8.0–11.5초 | 3.5초 | 4초 | 시작·사이 1·사이 2·끝 |
| ⑥-2 겨루기 | `c6b` | 11.5–13.0초 | 1.5초 | 3초 | 시작·사이·끝 |
| ⑥-3 승리 | `c6c` | 13.0–14.0초 | 1초 | 3초 | 시작·끝 |
| ⑥-4 환호 | `c6d` | 14.0–15.0초 | 1초 | 3초 | 시작·끝 |

- **앱에만 있는 단계**(다운로드 영상에는 빠짐): ④ 멈춤 — ③-3이 끝나면 **멈춤 정지 그림**(`P`)을 띄우고 «뭐라고 외칠까 ?» + 보기 2개 +
  «나만의 대사도 좋아요» → 3·2·1 → ⑤ 녹음 3.5초(«지금 소리치세요 !» + 남은 시간 막대, **BGM 끔**) → ⑥ 7초 재생에 아이 목소리를 겹쳐 바로 들려줌
- 다운로드 영상 = ①③⑥ + 아이 목소리, 15초. 자막은 상대 대사에만(③-2 구간, 화면 아래 가운데)
- 상대 대사는 **3.6초에 시작해 5.8초 전에 끝난다**(2.2초). 아이 목소리는 **8.0초부터 3.5초**

## 3. 그림 결 통일 — 프롬프트 공통부

| 항목 | 규칙 |
|---|---|
| 그림체 | 어린이 애니메이션 영화풍 2D 디지털 일러스트(실사·3D 금지). 장르 느낌은 그림체가 아니라 **색·빛·연출**로 낸다 |
| 선 | 짙은 적갈색, 굵기 일정 |
| 채색 | 셀 음영 2단계 + 하이라이트 한 겹 |
| 색 | 채도 중간~높게, 그림자는 짙은 남색, 주조 3 + 강조 1 |
| 빛 | 한쪽 주광 + 반대쪽 테두리광, 빛 효과는 부드러운 발광 |
| 비율 | 어린이 4.5등신, 어른 6등신(동생 «똘이»만 4등신, 로봇·유령은 예외) |
| 1인칭 | 주인공 얼굴·머리·몸통 금지 — 손·팔(·발)만 |
| 화면 | 3:2로 그리고 16:9로 자름 — 위아래 8%는 버려짐 |
| 금지 | 글자·자막·로고, 닮은꼴, 피·무기 위협·끔찍한 얼굴 |

아래 블록이 **모든 그림 프롬프트의 맨 앞에 글자 그대로** 들어 있다. 고칠 때는 일곱 문서에서 같은 블록을 한꺼번에 바꾼다
(찾아 바꾸기 — 한 문서만 고치면 결이 갈라진다).

```text
[공통 그림 결 — 장면 더빙 2.0의 모든 그림에 똑같이 적용]
1. 그림체: 어린이 애니메이션 영화풍 2D 디지털 일러스트. 사진·실사·3D 렌더처럼 보이면 안 된다.
2. 선: 짙은 적갈색 외곽선, 굵기는 일정하게(인물·소품은 또렷하게, 먼 배경은 가늘게). 스케치 선·거친 선은 쓰지 않는다.
3. 채색: 셀 음영 2단계(밝은 면·그림자)에 부드러운 하이라이트 한 겹. 그라데이션은 하늘·빛·발광에만 쓴다.
4. 색: 채도는 중간에서 높게, 그림자는 검정 대신 짙은 남색. 한 장에 주조색 3개와 강조색 1개.
5. 빛: 화면 밖 한쪽에서 오는 주광과 반대쪽 테두리광(림 라이트). 마법·빔·손전등 같은 빛은 부드럽게 번지는 발광으로.
6. 질감: 배경은 붓질이 살짝 보이는 페인터리 질감, 인물·소품은 매끈하게.
7. 비율: 어린이는 4.5등신, 어른·키 큰 캐릭터는 6등신. 눈은 크고(얼굴 높이의 약 1/4) 표정이 또렷하다. 손가락은 다섯 개, 모양이 정확하다.
8. 주인공(나): 1인칭 시점이라 얼굴·머리·몸통이 절대 보이지 않는다. 화면 아래 가장자리에서 들어오는 어린이의 손과 팔(남녀 구분이 안 되게, 중간 피부톤)만 보인다.
9. 화면: 가로 3:2(1536×1024)로 그린다. 위아래 각 8%는 영상에서 잘리므로 얼굴·손·중요한 물체는 가운데 84% 안에 둔다.
10. 넣지 않는 것: 글자·숫자·자막·말풍선·로고·워터마크, 실존 인물이나 유명 작품 캐릭터를 닮은 모습, 피·상처·무기로 위협하는 장면, 아이가 무서워할 끔찍한 얼굴.
11. 첨부한 참조 그림과 선 굵기·색감·빛·인물 비율을 똑같이 맞춘다. 참조 그림 속 인물·소품을 그릴 때는 얼굴·옷·모양·색을 하나도 바꾸지 않는다.
```

## 4. 그림 작업 순서와 규칙(ChatGPT)

> **2026-10-10 밤 대표님 지시로 결 승인 전에 전부 그린다** — «그림이랑 프롬·대본·스토리보드 싹 다 세팅까지 해 놓으면 아침에
> 하나씩 하면 된다». 아침에 대표님이 판타지부터 결을 보시고, 승인 때 결이 바뀌면 그 뒤 그림을 다시 그린다(크레딧 0 — ChatGPT 시간만 든다).

1. **공통 기준 2장**(`common-S1` → `common-S2`)
2. **판타지 전부** — 장르 기준 `G1`~`G6` → 키프레임(컷 순서대로, 컷 안에서는 시작 → 사이 → 끝, 앞 그림을 참조로 붙인다) → 마지막에 멈춤 정지 그림 `P`
3. **나머지 장르** — 애니메이션 → 호러 → 액션 → 드라마 → 시트콤, 장르마다 2와 같은 순서
4. **장르 사이 결 통일** — 여섯 장르의 `G1`·`G5`를 한 화면에 줄 세워 본다
5. **장르 검토 페이지** — 한 장르의 29장을 한 화면에 모아 대표님께 보인다(§6 관문 B). 판타지부터

- **대화는 장르마다 새로**(«VC2 판타지» 같은 이름). 긴 대화 끝에서 결이 흐려지면 새 대화에서 기준 그림을 다시 붙이고 이어 간다
- **한 번에 한 장.** 프롬프트는 장르 문서의 «프롬프트 전문»을 통째로 붙이고, 적힌 «첨부»를 함께 올린다(최대 5장)
- **파일 이름**: `vc2_<장르>_<그림 id>.png`(장르 문서 표에 적힘). 보관은 `_media/scenes/<장르>/` — 로컬 보관, Git·배포 제외
  (`.gitignore`에 `_media/scenes/`가 들어 있다 — 2026-10-10). 장르 검토 페이지도 같은 폴더의 `review.html`
- **다시 그리기 기준**: 공통부 위반(글자·실사·손가락 수·얼굴 노출), 참조 인물과 다름, 앞 그림과 구도·크기가 어긋남(사이·끝 그림),
  화면 위아래 8% 안에 중요한 것이 걸림. 한 장에 세 번 넘게 실패하면 프롬프트를 고쳐 이 문서에 반영한 뒤 다시 한다
- **대표님 Chrome 사용**: 시작 전에 팀장에게 한 줄(무엇 · 몇 장 · 비용 — ChatGPT 구독 안이라 추가 0, 사용 한도 `[확인]`)

## 5. 그림이 어디에 쓰이나

- **시작·끝**: Higgsfield 영상의 첫 그림·끝 그림(컷 하나 = 시작 → 끝)
- **사이 자세**: ① 영상이 그 자세를 거치지 않거나 망가지면 컷을 둘로 나눠(시작 → 사이, 사이 → 끝) 다시 만든다
  ② 컷이 끝내 실패하면 그림 + 카메라 움직임으로 대신할 때 중간 장면으로 쓴다
- **장르 기준**: 모든 키프레임의 참조. 화면에 직접 나오지 않는다
- **멈춤 정지 그림 `P`**: 앱의 ④⑤ 화면(16:9로 잘라 `pause.jpg`)

| 관문 | 언제 | 무엇을 보나 | 누가 |
|---|---|---|---|
| A | 그림 시작 전(지금) | 이 문서 묶음 — 시나리오·대본·프롬프트·결 규칙 | 대표님 |
| B | 장르 그림 29장 완성 | 장르 검토 페이지 — 결 통일(공통 기준과 나란히), 상대 일관성(시트와 나란히), 1인칭 규칙, 금지 요소, 컷 순서의 이어짐, 위아래 8% | 대표님 |

| D | 장르 15초 시사본 | 영상·소리·자막·앱 흐름 → 그 장르를 켤지 | 대표님 |

### 관문 C — «영상 만들기 전 확인»(대표님 10/10 밤: «"이제 이렇게 만들려고 한다"고 허락 맡고 만들어라»)

컷 하나를 만들 때마다, 생성 버튼을 누르기 **전에** 장르 검토 페이지의 «영상 만들기 전 확인» 칸에 아래를 **전부** 세팅해 팀장에게
보내고, 대표님 허락이 온 컷만 만든다. 장르 문서 §6이 이 칸에 그대로 옮겨 쓰는 원본이다.

| 넣는 것 | 내용 |
|---|---|
| 넣을 그림 전부 | 첫 그림(시작)·끝 그림(끝), 그 컷의 사이 자세 그림, 참조로 쓴 장르 기준 그림 — 실제로 뽑은 파일 그대로 |
| 넣을 글 전부 | 영상 프롬프트 전문(영문 그대로), 초별 연출(쓰는 구간·카메라·움직임·표정), 설정값(모델·화질·길이·소리·예상 크레딧) |
| 다시 만들기 조건 | **지금 기준: 생성 한 번마다 허락**(다시 만들기도 한 번씩). «같은 설정이면 3회까지 다시 허락 없이»는 **대표님 확인 대기**(10/10) — 확정 전에는 쓰지 않는다. 프롬프트·설정을 바꾸거나 컷을 사이 자세로 나눌 때도 당연히 다시 허락 |
| 상대 목소리 | 음성 합성도 같은 방식 — 넣을 문장·목소리 지시·엔진·예상 크레딧을 보이고 허락 뒤에만 |

## 7. 영상 만들기(Higgsfield) — 관문 C의 허락 뒤에만

- 모델 `kling3_0`, 모드 `std`(720p — 지금 앱 클립과 같음), 소리 `off`, 길이 3초(⑥-1만 4초), 첫 그림 = 시작, 끝 그림 = 끝
- 판타지 시범에서만 같은 컷을 `veo3_1_lite`(4초)·`kling3_0` `pro`로 한 번씩 비교한다(기획서 질문 1)
- 생성은 **한 번마다 허락**(지금 기준). 컷당 다시 만들기는 3회까지로 잡고, 넘으면 사이 자세로 컷을 나누거나 그림 + 카메라 움직임으로 대신한다
  («같은 설정 3회까지 다시 허락 없이»는 대표님 확인 대기)
- 크레딧 추정은 기획서 §10-1(최소 456 · 권장 약 995, 컷을 많이 나누면 최대 약 1,900). 실제 값은 생성 버튼에 먼저 뜨는 값으로 확인한다
- 영상 프롬프트는 도구 입력이라 영어로 적었다. 끝에 붙는 공통 문장: «Keep the exact art style, colors, lighting and character design of the start and end frames. 2D hand-drawn animated film look. No text, no subtitles, no logos.»

## 8. 소리 공통

- **음량**: 완성본 −16 LUFS 근처, 최고점 −1 dBTP
- **BGM 낮추기**: 상대 대사(3.5–6.0초) −4dB, 아이 목소리 자리(8.0–11.5초) −8dB, 앞뒤 0.15초 부드럽게
- **녹음 3.5초 동안 BGM 끔** — 스피커 소리가 마이크로 다시 들어가 겹쳐 울리는 것을 막는다(기획서 질문 6)
- **아이 목소리 처리**: 낮은 웅웅거림 제거(고역 필터 90Hz)와 찢어짐 방지(리미터 −1dB)
- **상대 목소리**: Higgsfield 안 음성 합성(ElevenLabs v4, 한국어) — **관문 C의 허락 뒤에만**. 어색하면 같이교육 선생님 녹음(녹음 동의서)
- **출처 기록**: BGM·효과음은 상업 이용 가능·출처 표기 불필요한 무료 음원만. 받을 때마다 `_docs/ops/scene-assets.md`
  (처음 받을 때 만든다)에 파일·주소·작가·라이선스·받은 날·SHA-256, 라이선스 화면 캡처는 `_media/licenses/`(로컬)

## 9. 앱 흐름 연결 — 장르마다 같은 방식

- **장르별 스위치**: `src/genres.ts`의 장르에 `scene` 설정이 있으면 새 흐름, 없으면 지금 흐름. 장르마다 따로 켜고 끈다
- **장르당 파일**(제안): `public/scenes/<장르>/scene.mp4`(15초 원판, 1280×720 H.264/AAC, 아이 자리는 BGM만 −8dB),
  `preview.mp4`(① 2.5초 고리, 무음, 작게), `pause.jpg`(멈춤 정지 그림을 16:9로 자름)
- **화면 순서**: 홈 카드(`preview` 무음 고리) → 상황(`scene` 2.5–8.0초) → 멈춤(`pause.jpg` + 문구) → 3·2·1 → 녹음 3.5초 →
  결과(`scene` 8.0–15.0초 + 아이 목소리) → «다시 하기 / 이대로 저장» → 저장·QR(지금 그대로)
- **합성**: 원판 영상은 그대로 복사, 소리는 원판 + 아이 목소리(8.0초에 맞춰 늦춤, 위 처리)를 섞어 AAC로. 15초 약 7MB(서버 한도 20MB 안)
- **서비스워커**: `clips/`처럼 `scenes/`도 미리 받기 목록에서 빼고 실행 중 캐싱으로 둔다(`tools/precache-plugin.js`의 제외 목록에 더함)
- **바꾸지 않는 것**: 서버(업로드 검사·저장 이름·한도·자동삭제), QR·공개 주소 고지, 개인정보 처리, 홈 카드 무음 원칙, H.264/AAC
- **예열**: 부스 기기에서 장르를 한 번씩 눌러 `scene.mp4`까지 받아 둔다(설치운영설명서에 추가)
