    모두. 시험용 PowerShell은 창 없이. 앱이 켜지며 최대화할 때는 처음부터 아래 모니터에 만든다(위에 그렸다 옮기지 않는다). 지킬 수 없는 시험은 멈추고 알린다.

## 기준 7(진행 화면) — 원인과 고친 방법

10/27 시안(템플릿 그대로)을 같은 도구로 재 본 원인(막대 0~30000):
- **막대가 뒤로 갔다** — 62% → **0%**, 99.7% → **64%**. NSIS는 명령 하나를 마칠 때마다 막대를 «명령 수 기준» 위치로 옮기고, 압축 풀기 플러그인(Nsis7z::Extract)도
  같은 막대를 제 기준(0→100%)으로 옮겨 둘이 번갈아 잡았다. 끝은 87%에서 100% 없이 완료 화면으로 넘어갔다.
- **막대가 오래 멈췄다** — 켜진 앱 찾기(PowerShell 세 번, 3초쯤), 임시 폴더 → 설치 위치 통째 복사(CopyFiles 한 번, 1.4초) 동안.
- **안내 상자가 없었다** — 템플릿은 «nevershow»로 상자를 숨긴다. 상자를 진행 중에 켜면(SetDetailsView show) 화면이 열린 뒤 상자가 튀어나온다.
- **글** — 켜면 «압축 해제: …\Temp\nsg….tmp\app-64.7z» 같은 임시 경로가 찍힌다.

고친 방법:
- 진행 화면이 뜨기 직전(SHOW) 같은 자리 · 같은 모양의 막대를 하나 더 만들어 이 설치기만 움직이고(앞으로만 — 작은 값이 오면 무시) 원래 막대는 숨긴다.
- 막대 몫은 이 PC에서 잰 단계 시간에 맞춘다: 압축 풀기 4~46%(푼 바이트) · 복사 46~84% · 설치한 파일 확인 86% · 시작 메뉴 90.5% · 바탕화면 95% · 끝 100%.
  예전 판을 지울 때는 그 몫이 앞 25%이고 위 몫이 남은 75%에 줄여 담긴다.
  복사는 «파일 크기(KB) + 파일 하나당 9MB 몫»으로 센다 — 작은 파일 100여 개가 실행 파일 247MB 한 개보다 오래 걸렸고(처음엔 파일 수로 셌다),
  영상이 커지면 그만큼 막대를 더 차지해야 해서다(기준 17). 실행 파일은 맨 먼저 복사한다.
- 🟠 **막대는 바로 그린다**(10/28 팀장 검토 4): Windows 막대는 앞으로 갈 때 새 자리까지 미끄러지듯 따라가 0.5초쯤 늦게 보였다. 한 칸 앞에 놓았다가 제자리로
  되돌리면(뒤로 갈 때는 바로 그린다) 그 자리를 바로 그린다(끝 1000은 범위를 한 칸 늘렸다 되돌린다 — `vcSetBarRaw`).
- 🟠 **단계 문장은 하는 일과 같게**(팀장 검토 1): 예전 판 지우기 «예전 Voice Cinema를 지우는 중입니다 …» → 압축 풀기 «설치할 파일을 준비하는 중입니다 …» →

  원인을 못 찾은 채 멈췄다(다시 시작하면 화면 제거에서 앱 데이터가 지워지는지부터 본다). 이 PC의 시험 설치본은 조용한 제거로 모두 지웠다.
- **App Check**: 사람이 연 것과 같은 방식(자동화 없이)으로 띄운 설치판은 교환 요청이 200. Playwright로 띄운 창은 403(웹 헤드리스와 같다).
- **업로드 서버까지의 길**: 설치판에서 `GET /`(배포 커밋) 200, 토큰 없는 `POST /upload`는 서버가 403으로 거절 — 요청이 처리기를 지나 그대로 나간다.
- **검사**: 설치판 유닛 9개(`desktop/test/`, node:test) · 설치판 E2E 6개(`desktop/e2e/desktop.spec.mjs`, 빌드한 exe — 첫 화면 · 권한 · QR · 기기 저장 ·
  인터넷 없음 · 창/바깥 주소) 통과. 웹 E2E 2개 추가(`e2e/dubbing-flow.spec.js` «인터넷이 없으면…», `e2e/background-load.spec.js` «서비스워커 등록이
  실패하면…») — 옛 코드에서 빨간불(문구 · 엔진 시작 23.7초) 확인. 루트 유닛 93 + functions 55 · 린트 통과.
  웹 E2E 전체는 멈춤 지시로 중간에 껐다(그때까지 177개 통과 · 실패 0 — 끝까지 돈 결과가 아니다).
- 🟠 **설치판 검사에서 업로드를 `page.route`로 가로채면 안 된다** — 설치판이 https를 직접 처리해 닿지 않는다. 처음 두 검사가 그렇게 짜여 업로드 요청이
  운영 서버까지 갔다(App Check 토큰이 없어 서버가 거절, 저장된 것 없음). 지금 검사는 `ses.fetch`를 바꿔 끼운다(`routeUpload`).
- 🟠 **NSIS 언어**: `multiLanguageInstaller: false`면 electron-builder가 `language` 값과 상관없이 영어만 넣는다 — `true` + `installerLanguages: [ko_KR]`.
- 🟠 **권한 확인 처리기가 받는 출처는 끝에 «/»가 붙는다**(`https://voice.edutogether.kr/`) — 문자열 비교가 아니라 `isBundleUrl`로 본다(처음엔 마이크 조회가 «거절»으로 나왔다).

## 남은 것 · 미검증 (10/28)

- 🟠 **Windows(백신)의 새 파일 검사를 기다리는 시간은 내용 크기 · PC마다 다르다** — 이 PC에서 복사 직후 0.34초(지금 내용) · 1.8초(영상을 키운 744MB),
  실행 파일 첫 열기 0.55~0.7초다. 그동안은 «설치한 파일을 확인하는 중입니다 …»가 떠 있고 막대는 84%에 선다(기다림 문장 — 팀장 판정 기준에서 뺀다).
  설치기는 한 줄기로만 돌아 기다리는 동안 막대를 움직일 수 없다. 영상을 크게 바꾸면 그만큼 길어진다.
- **권한 없이 예전 제거기를 띄우는 0.41~0.44초** — 새로 복사한 실행 파일을 Windows가 검사하는 시간이라 막대가 선다(판정 기준 0.5초 안). 느린 PC에서는 넘을 수 있다.
- **화면 크기 — 다른 배율 모니터로 끌어 옮기기** — 위 큰 모니터에 시험 창을 띄울 수 없어, 보이는 창을 다른 배율 모니터로 끌어 옮기는 것은 이 PC에서 보지 못했다.
  숨긴 채 옮겼다 돌아오면 돌아온 직후(1.5초)에는 비율이 옛 값에 머물렀고(숨은 창은 화면 갱신이 미뤄진다), 크기를 한 번 더 주거나 보이게 하면 그 크기의 값으로
  맞았다(resize-check — 새로 연 화면과 요소 차이 0).
- **NSIS 화면 배율** — 설치 · 제거 화면은 NSIS가 화면 배율을 모르는 프로그램이라 125% 모니터에서 Windows가 그림째 키운다(글자가 조금 흐리다).
- **아이콘 256 칸** — 원본이 160px이라 1.6배 키운 256 칸은 테두리가 조금 흐리다(기준 3에 따라 다른 그림을 만들지 않고 알린다). 쓰이는 곳은 탐색기
  «아주 큰 아이콘» 보기 등이고, 작업표시줄 · 시작 메뉴 · 바탕화면(배율 100~150%)은 원본보다 작은 칸(16~128)이라 선명하다.
- **관리자 승인 창** — 이 PC는 관리자 승인 창이 뜨지 않게 설정되어 있어(ConsentPromptBehaviorAdmin=0) «모든 사용자»를 고를 때 다른 PC에서 뜨는 승인 창은 보지 못했다.
  승인 창이 뜨는 동안에는 설치 창이 숨어 있다가 승인 뒤 위치 화면으로 다시 뜬다(템플릿 동작).
- **두 범위가 함께 깔린 PC의 «제거 옵션 선택» 화면** — 안내문만 같은 글꼴로 재 칸 안에 드는 것을 확인했다(화면은 띄우지 않았다).
  템플릿은 이 경우에도 화면을 띄우기 전에 «모든 사용자» 제거로 정해 관리자 권한으로 다시 뜬다(multiUser.nsh) — 실제로 이 화면이 보이는 경우는 드물다.
