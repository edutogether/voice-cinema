# 배포 대조 — 라이브가 master보다 뒤처지면 한 시간 안에 다시 배포한다

## 문제

2026-10-07 GitHub 장애로 옛 동시성 그룹(`deploy-voice-cinema`)에 배포 실행 셋이 잡 0개로 묶였다
(37642382427 `a357c51`, 37655509098·37655517245 `75ef607`). 취소·강제 취소·삭제가 전부 거부돼 지울 수 없다.

- `75ef607`의 둘은 끝 커밋 판정이 든 워크플로로 만들어져 풀려도 건너뛴다
- **37642382427은 그 판정이 생기기 전 워크플로라, 풀리면 `a357c51`을 그대로 배포한다** — 함수 의존성,
  파비콘 주소, `index.html`·`privacy.html`이 되돌아간다
- 언제 풀릴지 모르고, 풀린 것을 알아챌 장치가 없다

## 원하는 결과

- 라이브(Hosting·Functions)에 무엇이 배포돼 있는지 **라이브에서 직접** 알 수 있다
- 매시 한 번, 라이브가 master 끝(CI 통과)과 다르면 master 끝을 **지금 배포 경로 그대로** 다시 배포한다.
  같으면 아무것도 하지 않는다
- 수동 실행으로 "같음 → 건너뜀"과 "다름 → 배포" 두 경로를 라이브를 옛것으로 만들지 않고 확인할 수 있다

## 영향받는 사용자·시스템

- 학생 화면: 바뀌지 않는다. 배포 커밋 표시(`/version.json`)는 빌드 뒤에 써서 프리캐시·서비스워커 캐시
  이름에 들지 않는다 — 부스 기기 캐시(엔진 31MB)를 건드리지 않는다
- 함수: `GET /` 응답에 `commit` 한 칸이 붙는다(공개 저장소의 커밋 해시, 개인정보·비밀값 아님)
- 배포 워크플로(`deploy.yml`): 트리거 둘(`schedule`·`workflow_dispatch`)이 붙고, 판정 기준이 실행 기록에서
  라이브로 바뀐다. 같은 파일·같은 동시성 그룹(`deploy-voice-cinema-v2`)·같은 deploy 잡
- 운영 절차: 로컬 `firebase deploy`는 한 시간 안에 master 끝으로 되돌려진다 — 동결 중 긴급 수정도
  master push로 내보내야 한다(`app.md` 동결 절 갱신)

## 제약

- 배포는 **CI를 통과한 master 끝**만 한다
- 판정을 못 하면(master 끝·CI 결과·라이브를 못 읽음) **건너뜀이 아니라 실패**로 끝낸다(§21-1)
- 문서만 바뀐 커밋에는 배포하지 않는다(COMMON_STANDARDS §23) — 매시 대조가 이 규칙을 무너뜨리면 안 된다
- 11-07~11-14 동결 중에 무해해야 한다 — 동결본을 그대로 다시 올리는 것 이상을 하지 않는다
- 공개 저장소 — 취약점 상세를 저장소 문서·커밋·PR에 쓰지 않는다
- 판정 잡에서 CI가 돈 커밋의 코드를 실행하지 않는다(CodeQL 캐시 오염 지적, PR #11)
