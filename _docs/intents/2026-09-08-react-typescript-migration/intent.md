# 프론트를 바닐라 JS에서 리액트 + 타입스크립트로 다시 짠다

## 문제

프론트가 `docs/` 폴더 하나에 든 바닐라 JS/HTML이었고, **그 폴더가 곧 배포 폴더**였다.
소스와 배포물이 같은 자리에 있으니 다음이 전부 사람 손에 달려 있었다.

- **서비스워커 캐시 목록을 사람이 손으로 적었다.** 파일을 추가하고 목록 갱신을 잊어
  **앱이 통째로 안 뜨는 상태로 배포된 적이 실제로 있다**(App Check 번들 누락).
  `CACHE_NAME`도 사람이 올려야 했다.
- **인라인 `onclick` 속성 8개가 있었고**, CSP가 인라인 이벤트 핸들러를 막아
  **배포된 사이트에서만 버튼이 전부 죽는** 사고가 났었다. 로컬에서는 멀쩡했다.
- 상태 초기화 로직이 네 곳에 흩어져 있어, 한 곳을 고치면 다른 세 곳이 어긋났다.
- DOM을 직접 만지는 코드가 118곳이라 화면 상태와 변수 상태가 갈라질 여지가 컸다.
- 타입이 없어 클라이언트·서버가 공유해야 하는 값(`BOOTH_TOKEN`, 업로드 타임아웃)이
  어긋나도 실행 전까지 알 수 없었다.
- 내부 문서를 `docs/` 아래 만들면 **라이브 사이트에 그대로 공개되는** 함정이 있었다.

행사(2026-11-14)까지 두 달 남은 시점에서, 이 구조를 그대로 두면 앞으로 손댈 때마다
같은 종류의 사고를 다시 낼 자리가 남는다.

## 원하는 결과

대표가 목표를 명시적으로 올렸다 — **"동일하게 재현"이 아니라 "깔끔하게 다시 짜되
동일함을 증명"**. 그래서 원하는 결과는 두 겹이다.

1. **사용자가 보기에 아무것도 달라지지 않는다.** 화면·문구·타이밍·소리까지 체감이
   같아야 한다. "언어를 바꿨으니 이 정도 차이는" 같은 변명은 인정되지 않는다.
2. **이미 겪은 사고가 구조적으로 다시 날 수 없게 된다.** 사람이 잊어서 나는 사고는
   사람에게 주의를 주는 것이 아니라 잊을 자리 자체를 없애서 막는다.

구체적으로:

- 서비스워커 캐시 목록을 사람이 관리하지 않는다. **앱 셸이나 엔진이 목록에서 비면
  빌드가 실패해서 배포 전에 멈춘다.**
- 인라인 스크립트가 0개가 되고, `firebase.json`에서 CSP 해시를 지운다.
- `BOOTH_TOKEN`과 업로드 타임아웃이 클라이언트·서버에서 어긋나면 CI가 떨어진다.
- 전환 전후 화면을 **눈이 아니라 기계로** 대조해 차이 0을 보인다.

## 영향받는 사용자·시스템

- **실사용자**: 부스에 오는 학생 전원. 프론트 전체가 대상이라 영향 범위가 앱 전부다.
- **배포**: 배포 폴더가 `docs/`(소스 그대로)에서 `dist/`(빌드 산출물, gitignore 대상)로
  바뀐다. **배포 잡이 반드시 `npm run build`를 거쳐야 한다** — 안 그러면 빈 폴더가 올라간다.
- **GitHub Pages**: `docs/`가 사라지므로 Pages 빌드가 깨진다. 별도 판단이 필요하다.
- **부스 기기 캐시**: 프론트 산출물이 통째로 바뀌므로 모든 기기가 엔진 31MB를 다시 받는다.
- **서버(`functions/`)**: 이번 전환의 대상이 아니다. 건드리지 않는다.

## 제약

- **UI/UX가 체감까지 동일해야 한다.** 눈으로 "비슷하다"가 아니라 대조로 보여야 한다.
- **"일단 동작하게 / 차선책 / 나중에"가 없다**(헌법 §15). 코드에 `TODO`·`FIXME`·`임시`를
  남기지 않는다. 못 하면 멈추고 보고한다.
- **`public/vendor/`의 ffmpeg를 번들러에 태우지 않는다** — Worker + WebAssembly + blob:
  URL로 코어를 스스로 로드하므로, 번들러가 해시·재작성하면 경로 해석이 깨진다.
- **클립의 원본 오디오 트랙을 건드리지 않는다** — 최종 합성물엔 학생 음성만 들어가지만
  스튜디오 "미리 보기"에서는 학생이 이 원본 오디오를 실제로 듣는다.
- **되돌릴 수 있어야 한다** — 착수 전 상태를 태그로 남긴다.

판정 기준은 대표가 준 것을 그대로 썼다 — **"지웠을 때 사용자가 관찰할 수 있는 변화가
없으면 지운다."**

- 죽은 코드(`.badge` CSS, `"use strict"`, 불가능한 널가드, 죽은 eslint 설정)

### 사고를 구조적으로 막은 것

- **`tools/precache-plugin.js`** — 빌드가 산출물을 훑어 서비스워커 프리캐시 목록과 캐시
  버전(내용 해시)을 만든다. 앱 셸이나 `vendor/`가 목록에서 비면 **빌드가 실패한다.**
  `clips/`(37MB)만 일부러 제외해 런타임 캐싱으로 남겼다 — install에서 한꺼번에 받으면
  느린 와이파이에서 설치 자체가 실패한다.
- **인라인 스크립트 0개** — 리액트라 이벤트가 자연히 핸들러 속성이 아니다. `firebase.json`의
  CSP sha256 해시 2개를 지웠다. Vite의 modulePreload 폴리필도 같은 이유로 껐다.
- **`test/contract.test.js`** — `BOOTH_TOKEN`과 업로드 타임아웃이 클라이언트·서버에서
  어긋나면 CI가 떨어진다.

### 전환 중 실측으로 발견해 고친 결함

**서비스워커가 프리캐시 항목을 런타임에 다시 저장하면서, Hosting이 붙이는 `Vary: Origin`
때문에 캐시에 있는데도 못 찾는 상태가 됐다.** 저장할 때와 찾을 때의 요청 헤더가 달라서다.
**그대로 배포됐으면 행사장에서 인터넷이 끊긴 채 탭을 새로 열었을 때 앱이 아예 안 떴다.**
조회에 `ignoreVary: true`를 쓰고 재저장하지 않도록 고쳤고, 이 규칙을 AGENTS.md와 개별법에
함정으로 못박았다. `e2e/offline-boot.spec.js`가 실제 오프라인 상태를 만들어 매번 검증한다.

이 규칙은 나중에 **폴백 경로 두 곳에서 다시 빠져 있는 것**이 종합감사에서 발견됐다
(우연히 매칭돼 안 터졌을 뿐). 규칙이 가장 필요한 자리가 마지막 방어선이라는 것을 그때 적었다.

### 동일함을 무엇으로 증명했는가

착수 전 태그를 git worktree로 꺼내 **옛 앱과 새 앱을 동시에 띄우고 기계 대조**했다.

| 도구 | 보는 것 | 결과 |
|---|---|---|
| `tools/compare-visual.js` | 5개 화면의 문서 절대 좌표 + computed style 40여 개 | **차이 0건** |
| `tools/compare-attributes.js` | alt·aria·title·meta·lang·href·`<video>` 속성·요소 id | 78개 중 `#root` 하나 |

`#root`는 리액트 마운트 지점이라 구조상 불가피하고, 그 안의 `.wrap`이 좌표·스타일 모두
동일한 것을 화면 대조로 따로 확인했다.

**이 대조가 실제로 잡아낸 것**(눈으로는 못 찾았을 것들):

- **체감 차이 5건** — 스플래시가 첫 페인트에 없음, 진행바 표시 단계, 카운트다운 중 문구,
  엔진 실패 문구, `.privacylink`/`.chip .e` 값
- **요소 id 21개 유실** — 리액트로 옮기며 이벤트를 직접 붙이다 보니 더 이상 필요 없어진
  id를 빠뜨렸다. 화면에는 안 보이지만 테스트·자동화가 붙잡는 손잡이라, 사라지면 나중에
  엉뚱한 곳에서 깨진다. (커밋 `a960f30`의 제목은 "12개"라고 적었는데 이는 잘못 센 것이다 —
  실제로는 마크업 20개 + 파비콘 link 1개 = 21개다. 커밋 본문의 목록이 정확하다.)

좌표·스타일 대조는 "보이는 것"만 보므로, 화면에 안 보이는 값은 통과해도 조용히 바뀔 수
있다는 것을 이때 배웠다 — 그래서 속성 대조 도구를 따로 만들었다.

### 배포 파이프라인에서 잡은 것

배포 폴더가 `dist/`로 바뀌었는데 **배포 잡이 프론트를 빌드하지 않아 빈 폴더를 배포할
뻔했다.** 배포 직전에 발견해 `npm ci` + `npm run build` 단계를 넣었고, 스모크 검증도
"200이면 통과"에서 **번들 참조와 프리캐시 목록 확인**까지로 강화했다.

### GitHub Pages 폐지 (이 전환에서 파생된 별도 결정)

전환으로 `docs/`가 사라지자 Pages 빌드가 매 push마다 실패했고, 옛 주소는 **마지막 성공
빌드(전환 전 앱)를 계속 서빙**하고 있었다 — 즉 옛 주소에 오는 사람은 낡은 앱을 보고 있었다.
세 안(끄기 / `dist/`를 Pages에도 올리기 / 리다이렉트)을 산정해 올렸고 **대표 지시로
①끄기로 확정**됐다("옛 주소로 오는 사람 살릴 필요 없어. 가장 깔끔하고 완벽한 걸로").

Pages를 비활성화하고, `functions/index.js`의 CORS 허용 목록에서 `edutogether.github.io`를
빼고, 저장소 전체의 `github.io` 서술을 정리했다. **폐지 전 설정은 `build_type: legacy`,
`source: master /docs`** — 되살릴 일이 생기면 이 값이 필요하다.

### 전환 직후 종합감사

전환 당일의 새 코드를 대상으로 §7 방식(Opus 6개 항목·Sonnet 4개 항목 별도 호출)으로
감사했다. 발견된 진짜 결함은 전부 그 라운드 안에서 고쳤다 — 홈으로 나가도 영상·목소리가
계속 재생되던 문제, 첫 설치 시 새로고침이 작업을 날리던 문제, 서비스워커 탐색 폴백의
`ignoreVary` 누락과 실패 응답 캐싱, 배포 폴더에 있던 운영자용 안내문 공개, 영상 초기화
코드 3줄 중복, 합성 실패 경로 미검증.

## 작업 중 실제로 물어본 것

- **GitHub Pages를 어떻게 할 것인가** — 세 안을 나란히 올려 대표가 골랐다(①끄기).

  팀장이 복원을 승인했다.
