# 행사 주간 서버 예열 — 11/14까지 9~18시 5분마다 GET /

팀장 전달 Bumm님 직접 지시(11/9 0시대): «현장 시험은 화요일에 하지만 예열은 세 앱 다 지금부터 걸어. 둘은 14일까지».
Poster Studio의 keepWarm과 같은 방식으로 한다(그쪽은 읽기만 했다).

## 문제

- 오래 부르지 않은 뒤 처음 오는 요청은 서버 인스턴스를 새로 띄우느라 늦다. 라이브에서 잰 값: 인스턴스가 새로 뜬 뒤 GET / 1.74초(깨어 있을 때 약 0.003초),
  새 인스턴스의 첫 업로드 1.86초(깨어 있을 때 1.17초). 11/5 한 번은 9.2초였다(원인 확인 못 함).
- 부스에서 첫 학생의 «저장하기»가 그 늦음을 그대로 받는다.

## 원하는 결과

- 11/9 ~ 11/14, 매일 9:00 ~ 18:55(KST) 5분마다 GET /을 불러 인스턴스 하나를 깨어 있게 둔다.
- 업로드 · 메일 · 의견 · 카카오가 모두 같은 `voiceCinema` 함수라 이 한 번으로 다 데워진다.
- 11/15 00:00부터는 깨어나도 아무것도 부르지 않는다(예약식에 연도가 없어 내년 11월에도 깨어나기 때문).

## 제약

- 최소 인스턴스(minInstances)를 쓰지 않는다 — 쉬는 동안에도 돈이 든다.
- 부르는 자리는 인증이 없고 가벼운 GET /(배포 커밋만 돌려줌)뿐이다. 업로드 · 메일을 흉내 내지 않는다.
- 배포는 팀장이 미리 OK — 빌드 · 린트 · 유닛 → master push → CI 배포. 배포 직전 한 줄은 보고에 묶는다.

## 판단한 것

- 부르기에 실패해도 실행을 실패로 끝내지 않는다(Poster Studio와 같음) — 다음 5분에 다시 부르고, 실패해서 잃는 것은 예열 한 번이다.
- 예약 작업이 하나 늘어 셋이 된다(자동 삭제 · 의견 정리 · 예열). Cloud Scheduler 무료 몫은 결제 계정당 작업 3개이고,
  이 프로젝트의 결제 계정에는 이 프로젝트 하나뿐이며 예약 작업은 지금 둘이다(11/9 `gcloud billing projects list` · `scheduler jobs list`로 확인) — 셋째도 무료 몫 안이다.
  다른 프로젝트를 같은 결제 계정에 붙여 작업이 넷이 되면 한 달 약 0.10달러가 붙는다. 호출 수(6일 × 12시간 × 12번 = 864번)는 Cloud Run 무료 몫 안이다.
